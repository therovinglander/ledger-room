# SMB Cash Runway & Risk Signal / Filing Extraction

Small, honest proof-of-concept: turns raw SMB transaction data into structured,
traceable cash-flow KPIs (runway, burn rate, concentration risk, anomaly flags),
then has an LLM narrate the *structured facts only* — never raw transactions —
into a plain-English risk brief with citations back to transaction IDs. The
companion room does the same against accrual-basis financials, for a
filing-extraction audience.

Code computes every number (deterministic, unit-testable). The model reads
facts, not rows, and cites what it read. No number in the output is a model
guess.

**All financial data in this repo is synthetic**, generated by `src/` for a
25-business, 12-month portfolio. No real bank data, broker credentials, or
live-execution code. The one piece of *real* data this repo touches is a
small sample pull from the public SEC EDGAR API (`skills/edgar.py`) — see
below — which is a public-filing API, not private financial data.

## Why this exists

Scoped 2-3 day build to validate two things before claiming them on a resume:
structured financial extraction with traceability (Daloopa), and SMB cash-flow
visibility + risk signal (Relay). See `PROJECT.md` for full context.

Run any self-check with `python3 skills/<name>.py` from the `skills/` dir.
Run a room with `python3 rooms/<room>.py` from the repo root (optionally
pass one or more `business_id`s to scope it; `filing_extraction_room.py`
also takes `--edgar` to additionally pull and report on the 3 real sample
companies).

**Known caveat (documented, not hidden):** the SEC's `Revenues` XBRL tag was
deprecated by several filers in favor of
`RevenueFromContractWithCustomerExcludingAssessedTax` around 2018, so the
EDGAR pull's "latest revenue" figure for some companies is a few years
stale relative to net income/D&A/AR (which use tags still in active use).
Fine for proving the connector works end-to-end against real filings; a
follow-up would walk a priority list of revenue tags, not just `Revenues`.

## LLM backend

`skills/narrate.py` has two backends: `mock` (deterministic, template-based,
fully offline — what the self-check and both rooms use by default) and
`openai` (real Chat Completions call, requires `OPENAI_API_KEY`, not
exercised by the self-check since this environment's network access was
untested at build time for arbitrary external APIs beyond `data.sec.gov`).
